# Contratti fra le aree della correzione del 22 settembre

Durante la correzione dei reperti della caccia del 22/09 le aree (backend e
frontend) lavoravano in parallelo: questi sono gli accordi sulle interfacce fra
l'una e l'altra, `C1`–`C23`. Il codice li cita come «contratto Cn». Testo
originale, in inglese, come fu scritto per le aree.

C1 [AG-DISP → FE-MODALI] `GET /api/agenda/availability` accepts optional `exclude_appointment_id` (int, appointment of the salon). With it: that appointment does not count as busy, and the plan (items in order with their snapshot duration, soak/wait, operators; services retired from the list still allowed) comes from the appointment itself, like `client_availability` does for moves; `items` may then be omitted (if sent it is ignored). Riprogramma in ApptDetailModal passes it.
C2 [AG-DISP → FE-MODALI, FE-GRIGLIA] `AppointmentOut` gains `updated_at` (ISO datetime). `PUT /api/agenda/appointments/{id}` accepts optional `expected_updated_at`: if given and different from the current `updated_at` → HTTP 412 with message «L'appuntamento è stato modificato nel frattempo: ricarica e riprova». A PUT whose `items[].id` contains an id that is not a row of this appointment → also 412. 412 is never bypassed by `force` (the dashboard retries only 409 with force). Clients: on 412 reload the appointment (GET /api/agenda/appointments/{id}), show a toast, do NOT retry with force.
C3 [MARKETING → FE-CLIENTE-SHARED] `GET /api/marketing/client/wallet`: every gift card gets `spendable: bool` = the card can be spent by THIS client in the salon now: paid, active, not expired, balance > 0, and (recipient_client is the client, or the client is the buyer and there is neither recipient_client nor recipient_name) — the same rule as `gift_index` in agenda/api.py.
C4 [ACCOUNTS-STAFF-INV → FE-CLIENTE-SHARED] public catalog services (`PublicServiceOut`, also inside public packages if they list services) gain `soak_min: int`.
C5 [CLIENTI → FE-CLIENTI] `GET /api/clients/{id}/history` response gains top-level `sales_hidden: bool` (true when the viewer lacks the sales permission and sale data were withheld).
C6 [ACCOUNTS-STAFF-INV → FE-IMPOSTAZIONI] staff cash/HR data for viewers without permission are returned as `null` (never 0) plus `cash_hidden: true` on the object: `GET /api/staff/` items (month_revenue; hourly_cost unless owner or team scope), each row of `GET /api/staff/{id}/performance` (revenue), each row of `GET /api/staff/{id}/clients` (total_spent, visits, last_visit). The dashboard shows «•••» for null values.
C7 [ACCOUNTS-STAFF-INV → FE-IMPOSTAZIONI] inventory CSV/restock rows (`CsvRowIn`) accept optional `product_id`; when present it identifies the product (must belong to the salon) and wins over sku/name. The dashboard sends it for every row matched to a known product, and always sends `name` too.
C8 [ACCOUNTS-STAFF-INV → FE-IMPOSTAZIONI] `GET /api/staff/?include_inactive=true` also returns deactivated operators (with `active: false`).
C9 [INTEGRAZIONI → FE-IMPOSTAZIONI] `GET /api/integrations/yourang/status` gains `last_error: str` ("" when none).
C10 [CORE-INSIGHTS → FE-IMPOSTAZIONI] insights occupancy by weekday: `occupancy_pct` is `null` for weekdays with no capacity (closed / no shifts) instead of 0.
C11 [CORE-INSIGHTS → FE-IMPOSTAZIONI] insights endpoints are allowed to the owner OR to members whose role has scope `insights`; the dashboard shows the Insight section to the same people.
C12 [ACCOUNTS-STAFF-INV → FE-CLIENTE-SHARED] `ClientMeOut` (GET/PUT /api/auth/client/me) gains `marketing_consent: bool`; the client app toggles it with the existing `POST /api/marketing/client/marketing-consent {accepted}`.
C13 [CLIENTI → FE-CLIENTE-SHARED] public lead form `HookLeadIn` accepts optional `lang` ('it'|'en'), used for a NEW contact.
C14 [AG-CAPARRA → FE-CASSA-FEDELTA] `SaleLineOut` gains `service_name: str` ("" when no service).
C15 [CLIENTI → FE-CLIENTI] `PUT /api/clients/{id}` applies only the fields present in the body (it already should: verify) and writes only those columns; when `consents` flags change the SERVER stamps `<flag>_at` (and `marketing_revoked_at` on revocation), like `client_set_marketing_consent`. The dashboard sends `consents` only from the Consensi tab, and otherwise only the fields actually changed.
C16 [MARKETING → FE-CASSA-FEDELTA] `POST /api/marketing/loyalty-programs/{program_id}/accounts` body `{client_id}` (scope marketing): enrolls a client in a program whose enrollment is not automatic; 400 if already enrolled; returns the account like the accounts list does.
C17 [AG-CAPARRA → FE-CASSA-FEDELTA] checkout (`POST /api/sales/checkout/{id}`) when the deposit credit covers the whole (discounted) bill: the server accepts `payments: []`, deducts only up to the total and records/refunds the excess (settle_deposit_excess). The dashboard sends `payments: []` and shows «caparra eccedente da restituire: € X».
C18 [MARKETING → FE-CASSA-FEDELTA] loyalty programs of `type: "stamps"` accept only `earn_metric` in (`per_visit`, `per_service`); `per_euro` with stamps → 400. The dashboard defaults stamps to `per_visit` and shows the metric selector for stamps (visit/service).
C19 [ACCOUNTS-STAFF-INV → FE-IMPOSTAZIONI] `PUT /api/staff/{id}` applies only the fields present in the body (`service_ids` replaced only if present); the dashboard sends only changed fields and reloads the operator on `operator.*` live events.
C20 [CORE-INSIGHTS → FE-IMPOSTAZIONI] the live feed (SSE and 30 s polling) may re-deliver events already delivered (safety window against the id/commit race): the dashboard (`ctx.jsx`) must dedupe by event id.
C21 [MARKETING → FE-CASSA-FEDELTA, FE-MODALI] staff gift-card and coupon lists with `status=active` exclude expired ones (expires_at in the past); expired ones are listed under status `expired`. Codes (`code`) are masked (e.g. «••••1234») for viewers without the `marketing` or `sales` scope.
C22 [AG-LIFE → everyone] held client messages: a merged `appointment.moved` keeps the FIRST `old_start` of the merge (what the client last knew); undo never silences a change that stays in force. (Informational.)
C23 [AG-CAPARRA → FE-MODALI] `GET /api/sales/today-summary` keeps its fields and gains `deposit_refunded` (Decimal string, refunds of deposits done today); `cash_in` is net of it. RightRail shows «Incassato oggi» whenever cash_in ≠ total.
